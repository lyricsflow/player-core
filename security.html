Security Architecture

Security Policy

How Lyricsflow protects community data, restricts network perimeters, and isolates sensitive identifiers.

1. Maximum Security CORS Boundary

Cross-Origin Resource Sharing (CORS) is strictly locked down across all server endpoints. The API gateway permits origins exclusively matching verified domains:

  • Allowed Origin Pattern: https://(*.)spicyamll.online
  • Wildcard origins (*) are strictly denied. Unverified third-party origins are rejected at the edge.

2. Zero User ID Leakage Architecture

Lyricsflow treats third-party user identifiers (including Discord User IDs) as private system keys:

  • Client responses never include raw user IDs or account identifiers.
  • Public creator pages and audio links use sanitized usernames (/:username), not account numbers.
  • Profile metadata in transit is obscured against client network inspections.

3. Header-Isolated Bot Authentication

Bot-level ingestion routes are concealed from public schema docs (include_in_schema=False):

  • Authentication requires private cryptographic keys supplied via secure request headers (X-Bot-Key).
  • Sensitive tokens and secrets are stored strictly within environment variables and never logged or serialized into client responses.
